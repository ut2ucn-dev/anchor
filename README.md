# Anchor MVP на Netlify

Демо-застосунок для A/B-тестування: карта станцій, бронювання 15 хв – 3 год із наростаючою передоплатою, відкриття слота «поруч» через Bluetooth (імітація), бонуси, реферальна програма, анкета. Платежі не приймаються.

> Я не зміг відкрити документацію Netlify з робочого середовища. Усе, що стосується конкретної поведінки чи лімітів Netlify, позначено **«перевірте в документації Netlify»**.

## Архітектура

```
Браузер ── index.html + css/app.css + js/config.js → js/analytics.js → js/app.js
   │  до «Прийняти»: жодних запитів і записів (крім самого вибору)
   ├─ CONFIG.ANALYTICS_PROVIDER = "ga4" → gtag.js підвантажується лише після згоди → GA4
   ├─ CONFIG.ANALYTICS_PROVIDER = "own" → POST /.netlify/functions/track → Netlify Blobs
   │                                       GET /.netlify/functions/export?token=… → JSON / CSV
   ├─ анкета й контакт → fetch POST "/" → Netlify Forms (форми «survey», «contact» і «request»)
   └─ scenarios.html → 7 сценаріїв станції (старий демо-прототип)
```

| Файл | Що робить |

| `js/config.js` | **Усі числа й тексти**, які можна змінювати |
| `js/analytics.js` | Згода, A/B-рандомізація, `track()`, журнал подій, код сесії, GA4 / own |
| `js/app.js` | Інтерфейс і сценарії бронювання |
| `scenarios.html`, `js/scenarios.js` | 7 сценаріїв станції без змін у логіці |
| `privacy.html` | Політика приватності |
| `netlify.toml` | Папка публікації, функції, заголовки безпеки |
| `_headers` | Ті самі заголовки для розгортання перетягуванням |
| `netlify/functions/track.mjs` | Приймає події, перевіряє формат і розмір, пише в Netlify Blobs без IP |
| `netlify/functions/export.mjs` | Віддає події як JSON або CSV лише за `EXPORT_TOKEN` |
| `package.json` | Залежність `@netlify/blobs` для функцій |

## Чому A/B на клієнті, а не Split Testing Netlify

Split Testing у Netlify ділить трафік між **гілками Git**: кожен відвідувач отримує цілу версію сайту з однієї гілки. Нам потрібні кілька **незалежних** експериментів одночасно (повідомлення, заклик до дії, пропозиція, логотип, за потреби ще й ціни). Гілками це означало б десятки гілок, і варіант не потрапляв би автоматично в кожну подію аналітики. Клієнтська рандомізація дає 50/50 у кожному експерименті окремо, примусовий варіант через `#oA_mB_sA_cB` (s — повідомлення на вітанні, c — заклик до дії; канал — `#threads`, `#instagram`, `#kpi-a`, `#kpi-b`, `#qr`, можна разом: `#threads_sB`) і мітку варіанта в кожній події. **Окрема гілка не потрібна.**

## Що працює за якого способу розгортання

| | Netlify Drop (перетягнути папку) | Netlify CLI або Git |
|---|---|---|
| Сайт, A/B, банер згоди | так | так |
| GA4 (`ga4`) | так | так |
| Netlify Forms | ймовірно так, якщо ввімкнено виявлення форм; **перевірте в документації Netlify** | так |
| Заголовки безпеки | файл `_headers` (`netlify.toml` у такому режимі може не читатися; **перевірте в документації Netlify**) | `netlify.toml` |
| Функції `track` / `export` і Blobs (`own`) | **ймовірно ні**: функціям потрібна збірка із залежністю `@netlify/blobs`; **перевірте в документації Netlify** | так |

**Висновок:** для `ga4` або `none` достатньо Netlify Drop. Для власної аналітики (`own`) розгортайте через Netlify CLI або Git.

## Розгортання

### Варіант А. Netlify Drop (GA4 або без аналітики)
1. Заповніть `js/config.js` (див. розділ «Що заповнити»).
2. Відкрийте https://app.netlify.com/drop і перетягніть **папку проєкту цілком**: `index.html` має лежати в корені.
3. Без акаунта сайт тимчасовий: натисніть запропоноване збереження сайту й увійдіть.
4. Увімкніть форми: у сайті знайдіть розділ **Forms** і, якщо є кнопка ввімкнення виявлення форм, натисніть її, а потім **перезалийте** папку. Точну назву пункту **перевірте в документації Netlify**.
5. Оновлення: у сайті відкрийте **Deploys** і перетягніть нову версію папки. Адреса не зміниться.

### Варіант Б. Netlify CLI (усе, включно з `own`)
Потрібен Node.js 18 або новіший.
```bash
cd anchor-netlify
npm install                          # встановить @netlify/blobs
npx netlify-cli login                # відкриє браузер для входу
npx netlify-cli init                 # або: npx netlify-cli link — щоб прив'язати до наявного сайту
npx netlify-cli env:set EXPORT_TOKEN "довгий-випадковий-рядок-від-32-символів"
npx netlify-cli deploy --prod        # публікує сайт і функції
```
Змінну середовища можна задати й у панелі: **Site configuration → Environment variables → Add a variable**, ключ `EXPORT_TOKEN`. Після зміни змінної зробіть новий деплой. Назву меню **перевірте в документації Netlify**.

### Варіант В. Git
Завантажте папку в репозиторій GitHub. У Netlify: **Add new site → Import an existing project**, оберіть репозиторій. Команду збірки лиште порожньою, папку публікації — `.` (вона також задана в `netlify.toml`). Додайте `EXPORT_TOKEN` у змінні середовища. Кожен `git push` оновлює сайт.

## Аналітика

### Варіант 1. GA4
1. У Google Analytics створіть ресурс і **вебпотік** для адреси сайту на Netlify. Скопіюйте ідентифікатор `G-XXXXXXXXXX`.
2. У `js/config.js`: `ANALYTICS_PROVIDER: 'ga4'`, `GA4_ID: 'G-…'`.
3. Скрипт `gtag.js` завантажується **лише після «Прийняти»**. Рекламні сигнали вимкнено. Кожна подія несе параметри `exp_offer`, `exp_mascot`, `exp_price`. Код: `js/analytics.js`, функції `loadGa4` і `sendGa4`.
4. **Зареєструйте параметри як виміри:** Admin → Data display → Custom definitions → Create custom dimension. Scope: **Event**, параметр `exp_offer`, назва «Варіант пропозиції». Повторіть для `exp_mascot`, `exp_price`, а також `method`, `min`, `place`, `variant`. Нові виміри з'являються у звітах не одразу; затримку **перевірте в документації Google**.
5. Де дивитися:
   - **Realtime** — події в перші хвилини після вашого візиту.
   - **DebugView** (Admin → DebugView) — потік подій із параметрами одного пристрою; потрібен режим налагодження, наприклад розширення браузера Google Analytics Debugger.
   - **Explore → Free form** — рядки: Event name, виміри: «Варіант пропозиції», метрики: Event count і Total users. Це основний звіт для скриншота.

### Варіант 2. Власна (`own`)
1. `ANALYTICS_PROVIDER: 'own'`, розгортання через CLI або Git, задати `EXPORT_TOKEN`.
2. Події збираються в пам'яті й відправляються пачками до 50 штук кожні 8 секунд, а також при закритті вкладки. Так викликів функції в рази менше, ніж подій.
3. Функція `track` приймає до 32 КБ і 50 подій. Вона відкидає некоректні назви, чужі поля й поля на кшталт `ip`, `email`, `phone`; IP-адресу не записує.
4. Перегляд:
   - JSON зі зведенням за варіантами: `https://ВАШ-САЙТ/.netlify/functions/export?token=ВАШ_ТОКЕН&days=7`
   - CSV для Excel чи Google Таблиць: додайте `&format=csv`
   - Не публікуйте посилання з токеном.
5. **Ліміти:** кількість викликів функцій, обсяг Blobs і число надсилань форм на безкоштовному тарифі **перевірте в документації Netlify** (розділ цін і лімітів). Якщо ліміт перевищено:
   - тимчасово перемкніть `ANALYTICS_PROVIDER` на `'ga4'` (GA4 не навантажує Netlify);
   - або збільште пачку подій;
   - або перейдіть на платний тариф.

## Анкета й контакти (Netlify Forms)
- У `index.html` є приховані статичні форми `survey`, `contact` і `request` (заявка на нову станцію) з `data-netlify="true"` і пасткою для ботів `bot-field`. Це потрібно, бо форму, яку малює JS, Netlify не знаходить при деплої.
- Застосунок надсилає дані через `fetch POST "/"` з полем `form-name`.
- `survey` містить приховані поля `exp_offer`, `exp_mascot`, `exp_price`, `exp_msg`, `exp_cta`, `channel` і `session_code`.
- `contact` містить лише контакт, джерело і позначку згоди. Він не змішується з аналітикою й надсилається тільки з окремою галочкою.
- Відповіді: у сайті розділ **Forms** → форма → список надсилань. Там же є експорт у CSV і сповіщення на пошту (**Forms → Form notifications** або подібний пункт; **перевірте в документації Netlify**).

## Код сесії
У меню ☰ → «Приватність і дані» (і в анкеті) є код на кшталт `oA-mB-sA-cB|t412|b45|r1|f2`:
- `oA-mB` — варіанти тестів;
- `t` — секунди у застосунку;
- `b` — хвилин заброньовано;
- `r` — дій із реферальною програмою;
- `f` — показаних фактів.

## Що заповнити вручну

| Що | Де | Обов'язково? |
|---|---|---|
| `ANALYTICS_PROVIDER` | `js/config.js` | так: `'ga4'`, `'own'` або лишити `'none'` |
| `GA4_ID` | `js/config.js` | лише для `'ga4'` |
| `EXPORT_TOKEN` | змінні середовища Netlify | лише для `'own'`, мінімум 16 символів (краще 32+) |
| `PACK_100H_PRICE` | `js/config.js` | так, зараз 1600 грн — заглушка; від неї залежить «економія» |
| `FIRST_PARKING_MAX_HOURS` | `js/config.js` | так, зараз 2 год |
| `FACTS` | `js/config.js` | для варіанта mA: поки факти — заглушки «ЗАПОВНИТИ», логотип у варіанті A лише пульсує, а хмаринки не з'являються. Вписуйте тільки перевірені факти з джерелом |

## Чек-лист після деплою
1. Відкрийте сайт в анонімній вкладці. Має з'явитися банер. У DevTools на вкладці **Network** до натискання не повинно бути запитів до `googletagmanager.com` чи `/track`. На вкладці **Application → Local Storage** має бути порожньо.
2. Натисніть «Лише необхідні». Подій усе ще немає, у сховищі лише вибір.
3. Банер згоди (або меню ☰ → «Приватність і дані») → «Прийняти». З'являються запити:
   - для `ga4` — до `googletagmanager.com` і `google-analytics.com`;
   - для `own` — `POST /.netlify/functions/track` зі статусом 204 протягом ~8 с.
4. Відкрийте `#oA_mA`, `#oA_mB`, `#oB_mA`, `#oB_mB` (кожну в новій анонімній вкладці). Перевірте рядок `exp: …` (унизу бічного меню ☰, на комп'ютері ще й у статус-рядку телефона), текст пропозиції в меню ☰ → «Бонуси» і анімацію логотипа у верхньому правому куті мапи.
5. Бронювання «Я далеко»:
   - 90 хв → **15 грн**, 105 хв → **27 грн**, 180 хв → **60 грн**;
   - перша оплата відхиляється, повтор проходить.
6. «Я біля станції» → «Відкрити (Bluetooth)» → «Готово, двері зачинено» → «Забрати» → код → оплата → «Я забрав». На карті з'являється картка пропозиції.
7. Надішліть анкету й контакт через «Отримати пропозицію». Обидва мають з'явитися в **Forms**.
8. Телефон або DevTools шириною 360 px: немає горизонтальної прокрутки. Перевірте світлу й темну теми.
9. DevTools → **Console**: без червоних помилок. Помилка завантаження `feedback-data.json` на сторінці сценаріїв очікувана: це старий публічний дашборд відгуків, і такого файлу на Netlify немає.
10. Для `own` відкрийте `export?token=…` і перевірте, що події там є.

**Чесне формулювання:**
> MVP запущено [дата] на Netlify. Ми порівнюємо дві пропозиції (пакет 100 годин проти −50% на перше паркування) і два логотипи (анімований із фактами проти статичного). Варіанти призначаються випадково 50/50. За [N] днів зібрано [X] сесій від [Y] відвідувачів, які дали згоду на статистику: [a] у варіанті A і [b] у варіанті B. Клікнули пропозицію [c] і [d]; анкету заповнили [k] осіб. Вибірка поки мала, тому різниця між варіантами — орієнтир, а не статистично значущий висновок. Для висновку потрібно більше сесій у кожному варіанті. Платежі в демо не приймаються: ми вимірюємо намір (клік і контакт), а не покупку.
